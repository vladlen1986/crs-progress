Core architectural principle — User is login identity only

All PII (name, phone, avatar, emergency contact, home address) lives on Employee. User holds only login credentials, role/permissions, and preferences. A User cannot exist without an employee FK — enforced via required field. Display name everywhere = User's employee's first_name + last_name.

Locked DecisionApplied as
#1 Tenancy (Company + Property)User carries both company and property FKs. Every privacy rule filters on these.
#2 Custom Role + fixed Permission OSUser.role (FK) + User.extra_permissions (list of OS - Permission). No permissions stored directly.
#3 GDPR HybridTwo-step: deactivate (soft, reversible) → anonymize (hard, irreversible). Email stub preserves uniqueness.
#4 Subscription tiersCore module — always active regardless of tier.
#5 SearchBubble native <500 users, Typesense for larger companies.

Authentication & 2FA

  • Bubble native email+password, hashed+salted. /login route, "remember me" extends session to 30d.
  • 5 consecutive failed logins → 15 min lockout. Logged as login_failed.
  • 2FA optional per user — TOTP, compatible with Google Authenticator / Authy / 1Password. Plugin: Zeroqode TOTP (~$10-15).
  • Activation: Enable → QR code → verify 6-digit code → 10 backup codes shown once.
  • Enabling/disabling 2FA revokes all other sessions (forces re-auth).
  • Lost device recovery via backup code → forced 2FA reset. Admin rescue via admin.edit_user.
  • v1.1 parked Mandatory 2FA by Role — ships when Enterprise demands it.

Policy: min 10 chars, 1 uppercase, 1 number, 1 special char. No forced periodic expiry — NIST guidance against it (leads to weaker passwords).

Role Assignment

  • Single dropdown, sorted by role_level then alphabetically. Shows role icon + name + permission count.
  • Hard safeguards: admin cannot change own role · cannot assign the seeded Admin role unless already Admin · cannot strip Admin from the sole Admin user.
  • Save writes role_assigned to ActivityLog + notifies the affected user in-app. Optional session revocation (default no; recommended yes on downgrade).

Presence System v17.1

Distinct from Account Status

Account status (Active/Inactive/Anonymized) controls login. Presence (Online/Away/Busy/Offline) signals current availability — computed from Session activity + manual override.

  • Active Session <5min → Online · 5–30min → Away · else Offline. Manual override lasts 8h (or "end of shift").
  • Stored on User (not Session) so privacy rules stay simple.
  • WU-critical: writes throttled — User.presence_status written only when the computed value actually changes (staying Online all day = 1 write, not 96).
  • Presence changes NOT logged in ActivityLog (high-volume, low audit value).

· User Directory (Admin → Users)

  • Hybrid table/card view, toggle persisted in UserPreferences.
  • Filters: role, department, status, last-login. Search on email/first/last name.
  • Table columns: Avatar+Name, Email, Role, Department, Status, Last login, Created, Actions.
