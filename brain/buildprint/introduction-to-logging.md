# Introduction to logging
> Source: https://docs.buildprint.ai/introduction-to-logging-r1sfq · Captured: 2026-07-14

Buildprint captures your Bubble app's server logs and offers "filtering, time-series charts, log detail views, and automated monitors" as an alternative to Bubble's standard log viewer.

Logs are currently under a **waitlist** system — Buildprint will "enable apps as capacity opens up."

## How it works

- Buildprint continuously retrieves Bubble server logs and indexes them for searching within the Logs section.
- Synchronization is ongoing. High-traffic apps typically receive logs within minutes; lower-traffic apps may see delays "up to 3 hours" because Buildprint spaces out requests to minimize load.
- The Logs View and Explorer focus on **live** application logs; some projects may display configuration options for additional versions.

## What you get

- **View**: time-series visualization for workload units, action duration, unique users, workflows, errors, and error rate
- **Explorer**: search and filter by time range, log type, text, user email, or thing ID
- **Monitors**: automated alerting based on custom pattern-matching conditions

## Enabling logs

If logs aren't available yet:

1. Open your project
2. Navigate to Logs > View
3. Join the logs waitlist

Once Buildprint activates logs for your project, the View, Explorer, Monitors, and Configuration tabs become available.

## Requirements

The Buildprint collaborator account (connect@getbuildprints.com) must have "Logs permission in Bubble for the version you want Buildprint to sync." Permission errors display instructions on the Configuration page.
