- **Severity:** medium
- **Affected:** `pages/bTGbC/elements/bUona/bUfcd0/element.json` — `states.1.condition`, referenced 12 times across page `index`
- **PROPOSED fix (not applied):** Per the "Core rule" in `brain/buildprint/guidelines/editing-frontend-expressions.md` ("Reuse existing element data sources whenever possible. Do not duplicate equivalent... expressions if another element already computes the same data") and Bubble performance guidance in `brain/bubble-performance/03-building-the-page.md` on avoiding duplicate expression evaluation — move this condition onto the parent Group/RG (bUona) as a single custom state, then have the 12 descendants read via `GetElement(<bUona>).custom.<state_key>` instead of recomputing the same condition independently. This reduces redundant client-side evaluation on every re-render of `index`.

### Duplicated expression referenced 18x on index page (theme state on bUoGr)

- **PROPOSED fix (not applied):** Same convention as above but higher severity given the reference count (18) and that it's a theme-level state likely read by many descendants app-wide on the main SPA page — per `brain/buildprint/guidelines/editing-frontend-expressions.md`'s reuse rule and the `duplicate-expression-references-page` hint itself, centralize `bptheme` computation as a single custom state on the group/page and have all 18 consumers reference it via `GetElement` rather than re-evaluating the same condition each time. Given `index` is the single SPA page per the locked routing decision (`CLAUDE.md` "Routing: Single App page (SPA)"), this expression fires on every module render — worth prioritizing over the 12x case.
